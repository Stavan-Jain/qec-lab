The Doubling Argument

an analytic reduction for certifying code distance

Certifying distance is expensive

the plan: exploit the structure of this space·analytic reductions
2 / 14
For various families of practical quantum error correcting codes, one of the best ways to understand how effective the code will be in suppressing noise is to compute the distance of the code. Unfortunately, computing distance for BB codes is in general an NP-hard problem. Indeed for general qLDPC codes, the state of the art technique to certify distance is integer linear programming or SAT. Right now it is intractable to certify distance above 16–18 for BB codes. Over the past few weeks, I’ve been very interested in finding ways to reduce this computational burden.

Suppose we have a stabilizer code S, which defines a codespace C. Okay, so recall that distance is the minimum weight logical operator, which means that it commutes with the stabilizers, that acts nontrivially on the codespace C. We call these nontrivial logical operators. The key insight is that the space of logical operators has rich structure in a sense that I hope this presentation will make clear. The goal is to use this rich structure to find analytic reductions to the distance computation problem. In this presentation, I will show you one such analytic reduction, which I call the doubling argument.

BB codes and their covers

base and cover
the construction
3 / 14
Let’s take a BB code defined over the abelian group ℤℓ × ℤm with polynomials A, B. We can construct a “cover” code with the same polynomials A and B over the larger abelian group ℤ2ℓ × ℤm. Geometrically, you can think of the cover code as being defined on a torus with one loop twice as long. The technique I’m about to present allows us to find the distance of the larger cover code solely by performing computation or proving results about the smaller base code. The final theorem statement is that if the base code satisfies 3 conditions, then the distance of the cover code is twice the distance of the base code. For example, the gross code has parameters [[144, 12, 12]] and is a cover for a base code with parameters [[72, 12, 6]] and has double the distance as you can see. To go through this doubling theorem I think it will be helpful to first do a review of the construction of BB codes.

We start with an abelian group ℤℓ × ℤm. We take the group algebra of this abelian group and get a polynomial ring. In particular, elements of this polynomial ring are polynomials in two variables x, y where the power of x is less than ℓ and the power of y is less than m, with coefficients 0 and 1. We can view these polynomials as vectors by taking the support of monomials in the vector. For instance, let’s take ℓ = 2 and m = 4. There are 8 monomials, and [x², y, xy³] corresponds to the vector …

Qubits on a grid, stabilizers as stamps

even overlap ⇒ the stamps commute
[[72, 12, 6]] · A = x³ + y + y² · B = y³ + x + x²
4 / 14
The qubits of the code can be viewed as two blocks of the monomials of the ring (i.e. the basis of the vector space). Let’s take the [[72, 12, 6]] code with ℓ = m = 6 and polynomials A = x³ + y + y² and B = y³ + x + x². Then the qubits are two 6×6 blocks. For instance, these two blocks correspond to the monomial x²y. So then what do the stabilizers and logical operators look like in this view? You can think of stabilizers as stamps on this grid of a particular shape. Since BB codes are CSS codes, the stabilizers come in two flavors: there’s the X-type stabilizers and then the Z-type stabilizers. An X-stabilizer of this code corresponds to applying an X to these qubits. The corresponding Z-type stabilizer corresponds to applying a Z to these qubits. To define a valid stabilizer group, these X and Z stabilizers need to commute, which in this picture means that the X and Z stabilizers overlap in an even number of qubits. The nontrivial logical operators that we’re after to compute distance are precisely the operators that commute with these X and Z stabilizers, which means that they have an even overlap, but aren’t stabilizers themselves.

The cover code: two sheets

operators on gross live on two sheets over the base
5 / 14
I’m going to use the word “cycle” to refer to a logical operator that could be a stabilizer or a genuine nontrivial logical operator. In other words, I’m going to use the word cycles to refer to the operators that commute with all of the stabilizers. Now let’s take a look at the gross code, which has parameters [[144, 12, 12]] and is the cover code of the [[72, 12, 6]] code, which means that it has the same polynomials, but over ℤ₁₂ × ℤ₆ instead of ℤ₆ × ℤ₆. The qubits of gross are arranged in blocks that are double the size of the ones of the base. So we can think of operators on gross as living on two copies of the base code. We’ll call these two copies sheets. As you might expect, there’s a structural relationship between the logical operators of the cover gross code and the logical operators of the base code. To see this relationship, we’ll need to define two maps.

The fold map

The first map is the fold map. It takes an operator like [example], separates it into sheets, adds the sheets modulo 2. This gives us an operator in the base code. What do you think is the kernel of this map? That is, what operators do you think map to 0? We call these the diagonal operators.

This motivates the second map, which we’ll call a diagonal lift. It takes an operator in the base code like [example], and creates a cover operator by copying the operator onto the other sheet.

Folding: a lower bound for free

folding never increases weight·d(cover) ≥ d(base)
8 / 14
Okay, so what do these maps reveal about the structure between the operators of the cover code and the base code? So fold maps cover stabilizers to base stabilizers. And it also maps cover cycles to base cycles. Moreover, folding cannot increase weight. So if we have a cycle with weight d in the cover code, it must be mapped to a cycle in the base with weight at most d. So this immediately gives us a lower bound on the distance: if we can show that no cycles (including stabilizers!) in the base code have weight less than d, then no cycles in the cover code have weight less than d. So the distance of the cover code is at least the distance of the base code. The rest of the argument is tightening that bound: so going from at least d to exactly 2d.

Lifting doubles weight

the lift copies onto both sheets·weight exactly doubles
9 / 14
Diagonal lift also satisfies similar properties: it maps base stabilizers to cover stabilizers and base cycles to cover cycles. Moreover, the diagonal lift of a base operator has twice the weight of the base [similar to the previous slide’s diagram].

When lifts collapse: im Δ

the collapsing classes form im Δ·exactly half: dim 6 of 12
10 / 14
So a natural question at this point is whether nontrivial base logicals lift to nontrivial cover logicals. The answer is not always. We know that nontrivial logicals lift to cycles, but it’s possible that they can lift to stabilizers too. So what we need is a classification of when nontrivial logicals lift to stabilizers and when they lift to nontrivial logicals.

I won’t go into the details, but it turns out that there’s a subspace of the base logical operator space that we’ll call im Δ, whose elements diagonalize to stabilizers of the cover code. We can also show that the dimension of this space is half the dimension of the ambient logical operator space. So for the base code, the logical coset space has dimension 12, and im Δ has dimension 6.

Three fates of a cover logical

enough to show: dangerous ≥ 12 and safe ≥ 12·from the base alone
11 / 14
The dual question is whether nontrivial cover logicals fold to nontrivial base logicals. Again, the answer is not always. Three things can happen: p(v) can be 0, in which case v is diagonal and has twice the weight of p(v)’s base preimage. Since we know that the base code cycles have weight ≥ 6, we can conclude that these cover nontrivial logical operators have weight ≥ 12. This is the best case scenario. The second thing that can happen is that p(v) is a nonzero stabilizer. Let’s call these dangerous logicals. The last thing that can happen is that p(v) is a nontrivial base logical. Let’s call these safe logicals. At this point, it suffices to show that dangerous and safe logicals all have weight ≥ 12. And we want to show this by appealing purely to the properties of the base code. Let’s tackle the safe sector first.

The safe sector: confinement into im Δ

the im Δ floor gives the safe floor·a smaller check, often free analytically
12 / 14
So the big theorem here is that if a particular identity, which we’ll call (R), holds for the base cycles, then the image of a safe cover cycle under the fold map is in im Δ. And in particular, if the safe cycle is a nontrivial logical operator, then the image is a nontrivial logical operator in im Δ. So if we show that all the nontrivial logical operators in im Δ have weight ≥ 12, then we can conclude that all the safe nontrivial logical operators in the cover have weight ≥ 12, since folding never increases weight. But how do we show that all the nontrivial logical operators in im Δ have weight ≥ 12? So you can do this by brute force computation, or you can exploit the structure of im Δ further to prove this. The computational burden of certifying that the confinement classes have no light-weight nontrivial logicals is less than exploring the search space of nontrivial operators of the cover code. Unfortunately I don’t have a good answer as to how much better it is. But the good news is that in a lot of cases we can completely eliminate this burden via further analytic arguments.

The dangerous sector: light stabilizers

the only light stabilizers of the base
windowed light stabilizers·every dangerous logical weighs ≥ 12
[[72, 12, 6]] · A = x³ + y + y² · B = y³ + x + x²
13 / 14
Okay, now let’s talk about the dangerous logicals. These nontrivial logical operators fold into stabilizers. But of course the stabilizers in base can have low weight and so this doesn’t directly give us a bound. So a way we can approach this issue is by first classifying the stabilizers of the base with weight less than 12. We’ll call these the light stabilizers. It turns out that the base code only has two kinds of light stabilizers: those with weight 6 and those with weight 10. Now consider those with weight 10. I’ll omit the details, but it turns out that you can show that if a nontrivial logical of the cover maps to a stabilizer of the shape that has weight 10, then it must lose at least 2 ones. Similarly, consider those stabilizers with weight 6. We can show that if a nontrivial logical of the cover maps to a stabilizer of the shape that has weight 6, then it must lose at least 6 ones. Thus, every dangerous logical has weight at least 12. Of course this is not true for every code, but you can show that it is for base codes that have light stabilizers with a particular structure (they admit a windowed decomposition) that I won’t get into.

In summary, if you have a base code and consider the cover code with the same polynomials but over a larger abelian group, then given these conditions, the cover code has double the distance of the base code. The conditions are: 1. the base code has no cycles with weight less than d. 2. Condition (R) holds, and the nontrivial logicals of the safe sector have weight ≥ 2d, which implies that the safe logicals have weight ≥ 2d. 3. The light stabilizers of the base have a windowed decomposition, which implies that the dangerous logicals have weight ≥ 2d.

We have several examples of distance doubling pairs: [[72,12,6]] → [[144,12,12]] with A = x³+y+y², B = y³+x+x²; [[150,8,8]] → [[300,8,16]] with A = 1+x+y, B = xy⁶+xy¹⁰+x²y¹²; and [[180,4,10]] → [[360,4,20]] with A = 1+x+y, B = y⁴+x+x¹¹y².
