# Bravyi360 kernel certificates

This package reproduces the generated Lean certificates for the bivariate-bicycle
code on `Z30 × Z6` with `A = x^9 + y + y^2` and
`B = y^3 + x^25 + x^26`. The mathematical definitions, general certificate
soundness proofs, and stabilizer-code packaging live in QECLean.

The proof uses the quotient tower `360 → 180 → 90` qubits. Every bottom shadow
lies in a space generated by 43 certified vectors. A trellis bounds its population
of vectors of weight at most 22, and checked disjoint translation orbits attain
that bound using 274,011 representatives, including zero. Dual witnesses, peeling
forests, and small affine searches cover their fibers. The remaining lifts reach
58,130 middle shadows. Every physical cycle of weight at most 22 in a top fiber
over that table is proved to be a stabilizer boundary. An explicit weight-24
logical operator supplies the upper bound on distance.

The compressed inputs are candidate certificates, not trusted proof results.
Every finite claim used by the Lean theorem is checked by its kernel, and general
Lean lemmas connect the packed calculations to the physical chain complex.
Regeneration requires Python's standard library. It replays the small parity searches
from the recorded forest data; the original large-distance search is not rerun.

## Regeneration

From the qec-lab root, with QECLean checked out separately:

```sh
QECLEAN_ROOT=/path/to/QECLean python3 \
  experiments/bb_lab/scripts/bravyi360_kernel/generate.py --force
```

Without `--force`, the generator refuses to overwrite an existing generated file.
To reproduce and compare the files without changing QECLean:

```sh
QECLEAN_ROOT=/path/to/QECLean python3 \
  experiments/bb_lab/scripts/bravyi360_kernel/generate.py --verify
```

`--stage /path/to/new-directory` retains the intermediate files for inspection.
The default uses a temporary directory and removes it after completion. The
generator verifies every decompressed input's SHA-256 digest before running any
emitter. It writes only the generated modules in `module_map.json`; authored
proof modules are maintained in QECLean.

## Contents

- `*_manifest.json`: certificate hashes, emitter arguments, execution order, and
  generated outputs for each part of the proof.
- `certificates/`: compressed candidate data, including orbit representatives,
  trellis tables, affine search trees, dual witnesses, and reconstruction tables.
- `emitters/`: deterministic Python emitters and explicit proof templates.
- `module_map.json`: scratch-module names mapped to their public QECLean imports.
- `generate.py`: the common regeneration entry point and overwrite guard.
- `validate.py` and `KernelReplay.lean`: fresh source checking and complete kernel replay.

The generated-file banner names both the common entry point and the individual
emitter. Change the emitter or its certificate input, regenerate, then check the
result in Lean; do not edit the generated Lean file directly.

## Validation

The final change must include a complete QECLean build, its standard axiom audit,
a reproduction comparison, and measured checking of the entire new proof cone.
Kernel replay and source elaboration are separate measurements: replay must send
all new safe declarations to `Lean.Environment.replay` against only preexisting
library imports. Merely loading the final theorem's compiled imports does not
constitute this measurement. The replay rejects new axioms and missing private
proof data and requires the public distance theorem to be among the declarations
checked. See Lean's [proof validation documentation](https://lean-lang.org/doc/reference/latest/ValidatingProofs/).

A reproducible validation run uses a fresh output directory and the QECLean
revision preceding this development:

```sh
python3 experiments/bb_lab/scripts/bravyi360_kernel/validate.py \
  --qec-root /path/to/QECLean \
  --base-revision 9dced20836a1e868d20a4cad109e56bdf0ccdaf2 \
  --output /path/to/new-validation-directory --profile
```

The driver checks every transitive QEC baseline source against that revision,
builds the baseline, and then runs the full QECLean build with its actual compiler
options, cache downloads disabled, and `LAKE_ARTIFACT_CACHE=false`. Before that
build, it preserves any existing
compiled artifacts for the new modules under `previous-artifacts/` in the output
directory and removes their working copies and build traces. This forces fresh
source checking while leaving source files and preexisting library artifacts
intact. The newly compiled proof objects and their preexisting QEC import closure are
then copied to the output directory for replay.
It records source and compiled-object hashes, separate source-check and replay
times, the toolchain, required public theorems, and individual logs. The driver
checks the recorded inputs again before and after replay; integrity-check time
is recorded separately. Identical theorem exports shared by compiled modules
are coalesced only when their types, proof bodies, and metadata match exactly. Replay
defaults to a strict 900-second elapsed-time limit including imports and object
loading. Its clock includes system sleep (`CLOCK_MONOTONIC_RAW` on macOS and
`CLOCK_BOOTTIME` on Linux). `--profile` additionally times each declaration through the same kernel
replay implementation. Neither the native compilation of the checker nor a
cached import is used as a proof certificate: every new safe declaration is
submitted again to Lean's kernel.


## Recorded result

The final source build and complete kernel replay passed on an Apple M4 with
16 GiB of memory, using Lean 4.30.0-rc2. Replay accepted 39,227 safe declarations
from all 331 new proof modules. The public distance theorems and packaged
`StabilizerCodeWithDistance 360 12 24` depend on exactly
`[propext, Classical.choice, Quot.sound]`.

An independent `mach_continuous_time` monitor conservatively enclosed the entire
replay in less than 807.917 seconds (13 minutes 28 seconds), including startup,
imports, dependency auditing, and object loading. No system sleep occurred during
that interval. The fresh library build took 2,799.719 seconds of awake elapsed
time; it was interrupted by system sleep and is separate from the kernel timing.

The validation evidence preserves the validator actually used for that run.
Its outer Python timer excluded sleep, so those original measurements are labeled
as active monotonic time. The separate sleep-inclusive monitor establishes the
elapsed-time bound. The current validator directly uses a sleep-inclusive clock;
its deadline regression tests run with:

```sh
python3 -m unittest discover \
  -s experiments/bb_lab/scripts/bravyi360_kernel -p test_validate.py
```

Portable evidence is recorded in [`validation/`](validation/): the source and
compiled-object hashes, replay summary and compressed profile, elapsed-time
measurement, original validator, and all eleven passing repository/reproduction
checks. `evidence-manifest.json` hashes these files. The full QECLean axiom audit
accepted 47,197 declarations across 521 modules.
