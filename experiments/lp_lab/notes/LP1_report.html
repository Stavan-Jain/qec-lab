Weight-6 quantum LDPC codes that are not bicycle codes, with the bicycle hardware package

Lifted products LP(A, b⊗I) with a 2×2 base matrix A = [[p,1],[1,q]] over F₂[G] inherit every hardware property of the Bravyi–Cross–Gambetta–Maslov–Rall–Yoder codes — degree-6 Tanner graph of thickness two, the 7-CNOT-layer syndrome cycle, and a toric layout — yet are provably not two-block group-algebra codes. Two instances below tie or exceed the best published weight-6 codes at their (n, k).

The layout the hardware sees

C224 on the torus Z₁₆ × Z₂₈. Every vertex has four nearest-neighbour couplers (grid) and two long-range ones, exactly as in Fig. 1B of the BB paper — but here the long-range shifts differ between the two copies of the group, which is what breaks the group-algebra structure. Wrap-around grid edges are omitted.

What the family is

Take a finite abelian group G, R = F₂[G], a weight-2 polynomial p containing 1, any weight-2 polynomial q, and a weight-3 polynomial b. The code is the CSS code with

H_X = [ A | b* I₂ ],   H_Z = [ b I₂ | A† ],   A = [[p, 1], [1, q]]   (blocks are |G|×|G| circulants)

Bivariate bicycle codes are the 1×1 case H_X = [A | B]. Each row of A holds three monomials, so every check has weight 6 and every qubit sits in three X and three Z checks. Relabelings reduce any connected 2×2 pattern to this normal form.

Why the BB hardware results carry over

The BB paper's thickness-two decomposition (Lemma 2) and the correctness proof of its depth-7 syndrome cycle (Table 5) use a single structural fact beyond "A and B are sums of three permutation matrices": every B-permutation commutes with every A-permutation. Here B = b⊗I is a scalar over the group ring, so this holds automatically.

Thickness 2 — The layers {A₂, A₃, B₃} and {A₁, B₁, B₂} are disjoint unions of planar wheel graphs. Checked mechanically with a planarity test for all nine layer choices on both codes.
Depth-7 cycle — The eight-round schedule measures every check and acts trivially on logicals (the round-6 step needs B A₂ = A₂ B). Stim confirms all detectors of the noiseless memory circuit are deterministic for both codes and both bases.
Toric layout — If σ = A_jA_i⁻¹ and τ = B_gB_h⁻¹ generate a group acting regularly on the L qubits as Z_μ × Z_λ, the Cayley graph of Z_{2μ} × Z_{2λ} is a spanning subgraph, with explicit coordinates. For a = 2 the criterion is G = ⟨p₁q₁⟩ ⊕ ⟨b_g − b_h⟩; the torus is Z_{4·ord(p₁q₁)} × Z_{2·ord τ}. Verified edge by edge.
Not a 2BGA code — A two-block code from commuting permutation sums with both permutation groups transitive is a group-algebra code; a group-algebra code is check-transitive. nauty finds two X-check orbits for both codes, so they are not 2BGA codes for any group and in particular not BB codes.

Designing instead of sweeping

Blind sweeps at n = 144 over every abelian group of order 36 capped at [[144,8,12]] for this class, and the reason is structural: the constituent classical code ker b lives on one copy of G, of length n/4 rather than the n/2 of a bicycle code. Two exact facts then turn the search into design:

k — k = 2·dim F₂[G]/(b*, 1 + pq); it is maximal, k = 2·dim ker b, exactly when pq ≡ 1 (mod (b*)). (Frobenius annihilator duality; the unconjugated version is false for even |G|.)
Cap — The X-logical (u, 0), u ∈ ker b, gives d ≤ D_b := d(ker b), so kd²/n ≤ δ_b D_b²/(2|G|), with D_b computed exactly.

So for each (G, b) with a strong low-dimensional kernel we enumerate only the (p, q) with pq ≡ 1 mod (b*) — a few thousand codes per b instead of millions — and screen them by randomized information-set decoding. The Z₅₆ table already explains the published coset code [[224,12,16]]: b = (1+x+x³)² has a [56,6,16] kernel and cap 13.71.

C224 ties the coset code in parameters; it adds an explicit polynomial description, the k and cap formulas, and a toric layout (the coset paper lists such layouts as open). C288 would beat the known BB code at (288, 8) if d = 22 holds. Fom records at n ≈ 250–340 stay with the twisted-torus BB codes; the contribution here is a new non-bicycle structure that keeps the full hardware package, plus a complete design theory for it.

Certificates and caveats

  • Exact distance. CryptoMiniSat ladder with native XOR rows and translation-orbit symmetry breaking (one instance per qubit orbit), validated against a plain-SAT-certified [[144,8,12]] (7–11× faster per rung). 14 ≤ d ≤ 16 certified (SAT: w ≤ 13 UNSAT; SAT witness of weight 16); rungs 14–15 running. C288: d ≥ 14 certified (SAT: w ≤ 13 UNSAT, 1800 s), d ≤ 22 (ISD 3000 trials); exact value open.
  • Circuit-level distance. BP-OSD random-η search (paper §6 method; 600 trials on 2 cycles, 150 on 4) finds no fault set below the code distance for either code (C224: ≤ 19 Z / ≤ 20 X; C288: ≤ 33), while the same budget does find d_circ ≤ 11 < d for the gross code (paper: ≤ 10). So d_circ ≤ d trivially and no circuit-level degradation was detected. Distance preservation is therefore open — the same status the BB paper reports for its codes other than [[72,12,6]].
  • Relation to coset codes. Formally LP(A, b⊗I) is a coset code with the wreath group Z_N ≀ S₂ and central b; the coset paper searched small GAP groups, not these lifts.
  • Screening trap recorded. Early-stopped ISD values are not estimates; one k = 16 "d = 16" lead at n = 288 was retracted (true d ≤ 12).
  • Both codes have no weight-4 stabilizers (minimum stabilizer weight 6).
